# FAQ：传输与任务

## Bot 一直显示“在排队”

依次检查：

1. CloudDrive2 是否已经登录；
2. 115 是否已经添加并能正常浏览；
3. WebDAV 是否开启；
4. WebDAV 用户名和密码是否正确；
5. 目标路径是否正确；
6. `/status` 中目的端状态是否正常；
7. VPS 是否触发磁盘安全线；
8. 当前 CPU、内存或网络是否触发动态调度限制。

## 单文件超过 20GB 会怎样

默认本地任务预算为 20GB 时，单文件超过预算不会要求你把预算调大，而是自动切换为流式模式：

```text
Telegram → rclone → CloudDrive2
```

流式模式不在 VPS 保留完整文件副本，因此中断后需要从头重试。CloudDrive2 仍可能使用自己的缓存，磁盘安全线继续有效。

## 115 已经看到文件，为什么 Bot 还显示“待确认”

这是正常设计。

```text
Bot 传输已完成，115 官方端待确认
```

表示 TG115 已完成 WebDAV 写入、远端大小校验和本地清理，但 TG115 没有把 CloudDrive2 的状态当作 115 官方端最终完成证明。

在 115 官方客户端确认文件大小正常且可以打开/播放后执行：

```text
/confirm <任务编号>
```

`/confirm` 只记录人工确认，不会再次上传、移动或删除文件。

## 为什么速度不一定能跑满 VPS 带宽

实际速度同时受到：

- Telegram 下载速度；
- VPS 国际线路；
- VPS CPU / 内存 / 磁盘；
- CloudDrive2 WebDAV；
- CloudDrive2 自身缓存与处理；
- 115 服务状态；
- TG115 动态资源调度。

因此“VPS 端口 1Gbps”不等于端到端一定能达到 1Gbps。

## 文件最终保存在哪里

TG115 将文件直接保存到：

```text
WebDAV 根目录 + 可选子目录
```

不会自动按年份或月份创建文件夹。

例如 WebDAV 根目录已经是：

```text
115open/Telegram
```

且 TG115 子目录留空，则最终路径类似：

```text
115open/Telegram/视频文件名.mp4
```

## 为什么出现重复目录

如果 WebDAV 根目录已经指向 `115open/Telegram`，又在 TG115 中填写 `115/Telegram`，会形成重复嵌套。

这种情况下 TG115 子目录应该留空。

## 失败后本地文件会被删除吗

普通落盘模式会在远端验证成功前保留本地完整文件；上传失败时保留本地副本以便后续重试。

流式模式本身不保留完整本地副本，所以中断后需要从头重试。
